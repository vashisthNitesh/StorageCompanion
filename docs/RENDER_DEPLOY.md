# Deploying SmartSpace on Render

SmartSpace deploys as one Docker web service defined in `render.yaml`. The container builds the
Vue frontend, runs migrations on start, seeds plans, creates the master admin, and serves
everything through nginx on `$PORT`.

## 1. Create or sync the service
1. In the Render dashboard choose **New → Blueprint** (or **Sync** an existing blueprint) and pick
   this repository. Render reads `render.yaml`.
2. The service keeps the name `speedcloud` so the existing service is updated rather than replaced.

## 2. Environment variables

Values marked *secret* are `sync: false` in `render.yaml`: set them in the dashboard.

| Variable | Required | Notes |
|---|---|---|
| `DATABASE_URL` | yes, secret | Neon/PostgreSQL connection string. |
| `SECRET_KEY` | yes | Generated by Render. Signs sessions and tokens. |
| `VAULT_KEY_SECRET` | yes, secret | Derives vault keys for Google-created accounts. **Set it to the current `SECRET_KEY` value before the first deploy of this version**, then never change it. Afterwards `SECRET_KEY` can be rotated freely. |
| `MASTER_ADMIN_EMAIL` / `MASTER_ADMIN_PASSWORD` | yes, secret | The admin account is created or its password updated on every start. Use 12+ characters. |
| `GOOGLE_CLIENT_ID` | for Google sign-in | OAuth client of type *Web application*. Add the site origin (e.g. `https://smartspacedata.com`, the `onrender.com` URL) to **Authorized JavaScript origins**. Without it the Google button shows as unavailable. |
| `SPACEBYTE_ACCESS_TOKEN` | yes, secret | Without it uploads and downloads fail (the admin console shows *Not configured*). |
| `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` | for payments, secret | Checkout is disabled until set. The old `rzp_test_sample` / `sample_*` placeholders are treated as unset. |
| `RAZORPAY_WEBHOOK_SECRET` | for webhooks, secret | In Razorpay → Webhooks, point to `https://<your-domain>/api/v1/webhooks/razorpay`, subscribe to `payment.captured`, `order.paid` and `payment.failed`, and use the same secret. |
| `BUSINESS_GSTIN`, `BUSINESS_STATE_CODE`, `BUSINESS_ADDRESS` | for tax invoices, secret | Without a GSTIN invoices are issued as payment receipts. `BUSINESS_STATE_CODE` is the two-digit GST state code (e.g. `07` for Delhi). |
| `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS` | yes | Set in `render.yaml`; add any custom domain. |
| `WEB_CONCURRENCY`, `GUNICORN_THREADS` | optional | Default 1 worker × 8 threads (fits the free plan's memory). |

## 3. After the first deploy
- Open `https://<service>.onrender.com/api/v1/health` → `{"status": "ok"}`.
- Sign in with the master admin; the admin console's storage pool card must say *Connected*.
- Make a test payment in Razorpay test mode and confirm the invoice downloads.

## 4. Plan expiry
There is no background worker. Run **Admin console → Run expiry check** regularly, or add a Render
cron job running `python manage.py process_expired_subscriptions` from `/app/backend`.

## 5. One-time cleanup from the security review
- Rotate the admin password, the Neon database password and the SpaceByte token; all three were
  exposed in the repository or local files.
- If an earlier test run created a `test_neondb` database on Neon, drop it.
- Remove the old placeholder Razorpay values from the service's environment.
